# Contributing to RoutePlex

Thanks for your interest in contributing! This guide applies to all RoutePlex repositories.

## Getting Started

1. **Fork** the repository
2. **Clone** your fork locally
3. **Create a branch** from `main` (e.g. `fix/typo-in-readme`)
4. **Make your changes**
5. **Push** to your fork
6. **Open a Pull Request** against `main`

## Pull Request Guidelines

- **One PR per change** — keep PRs focused and reviewable
- **Squash merge only** — all repos use squash merging, so commit history in your branch doesn't matter
- **PR title** — use a clear, concise title (this becomes the commit message)
- **Description** — explain what changed and why
- **All conversations must be resolved** before merging

## Reporting Bugs

Use the **Bug Report** issue template. Include:

- SDK/package version
- Language/runtime version
- OS
- Steps to reproduce
- Expected vs actual behavior
- Full error output

## Requesting Features

Use the **Feature Request** issue template. Include:

- What you'd like
- Why it's useful
- Example code showing the ideal API

## Security Vulnerabilities

**Do NOT open a public issue for security vulnerabilities.**

Email [security@routeplex.com](mailto:security@routeplex.com) with:

- Description of the vulnerability
- Steps to reproduce
- Impact assessment

We'll respond within 48 hours.

## Code Style

- **Python**: Follow existing patterns in the repo, type hints encouraged
- **JavaScript/TypeScript**: Follow existing patterns, JSDoc for public APIs
- **Commits**: Short, descriptive messages in imperative mood ("Fix typo", not "Fixed typo")
